# Daily — договорённости по итогам интервью

Дата: 1 ноября 2026. Статус: первая самостоятельная тестовая версия Daily 0.1.0 реализована.
Дизайн выбран по последним уточнениям ниже. Этот файл описывает намерения,
а не готовые функции. Новое приложение — самостоятельный проект без зависимости
от исходников и каталога старого Notes. Исходники находятся в web/.

## Актуальное платформенное решение · 2 ноября 2026

Daily — кроссплатформенное PWA с единой кодовой базой для iOS, Android, macOS
и Windows. Адаптивные экраны смартфона, планшета и компьютера; Safari, Chrome
и Edge; установка через Web App Manifest; touch, мышь/трекпад и клавиатура.
Приоритет — iPhone и Mac, без критической зависимости от Apple-специфичных API.
Различия браузеров/ОС учитывать адаптерами и проверкой возможностей, основные
сценарии должны иметь доступные альтернативы жестам и датчикам.
Офлайн-основа уже есть; её развивать и проверять на всех платформах. Push —
будущий этап с учётом разрешений и поддержки, не обязательная зависимость.
Полные правила и матрица: PLATFORMS.md. Это решение уточняет ранние пункты
интервью про работу только на устройствах владельца. Готовность подтверждается
TESTING.md, а не самим наличием требования.

## Назначение

Личный ежедневник для готовых задач. Пользователь быстро выгружает задачу из
головы, затем выбирает, чем заниматься по настроению и обязательности. Система
не должна требовать постоянной сортировки и заполнения дополнительных полей.
Первым делом в дне нужно видеть назначенное время: встречи задают рамки дня.
День обычно включает задачи разных проектов и личные дела, а не один фокус.

## Понятия

- Проект: MOST, Возвраты, Инстаграм, FCKNG banks и другие направления.
- Цель (рабочее название): например, «Запустить новый тариф» внутри MOST.
- Задача: конкретное действие внутри цели или самостоятельное действие.
- Проект и цель для задачи необязательны. «Личное» можно создать по желанию.
- План / выбранный день: задачи с датой. Общая очередь: задачи без даты.
  Это окончательное значение очереди из интервью, а не старый эксперимент
  Notes с двумя разделами внутри одного дня.
- Важность: один ручной признак «обязательно / очень важно», без уровней,
  закрепления и эмодзи в названии. Размер и длительность вручную не отмечать.

## Даты, выполнение, незавершённое

- Одна дата: когда вспомнить о задаче и заняться ею. Отдельного дедлайна нет.
- Время — назначенное время дела, не время уведомления.
- Новая задача получает открытый день, в том числе в будущем. В форме есть
  быстрый выбор «Без даты» для общей очереди.
- Невыполненные прошлые задачи остаются заметными на главном экране до
  выполнения или ручного переноса. Не становятся автоматически обязательными
  сегодня и не исчезают в массе общей очереди. Точная композиция ещё выбирается.
- Выполненное показывать зачёркнутым внизу дня, не прятать за раскрытием.
- Фактическая дата выполнения определяет день показа результата и статистику.
  Просроченная задача: стояла 20 октября, сделана 10 ноября — результат 10 ноября;
  с 20 октября исчезает.
- Выполнена заранее: стояла 4 ноября, сделана 2 ноября — результат 2 ноября,
  а 4 ноября остаётся выполненной с обозначением «сделано заранее».
  Это одна задача: статистика учитывает её один раз.
- У шагов одной цели могут быть разные дни. В ежедневнике показывается шаг с
  пометками проекта и цели; из него можно перейти к полной цели.
- Цель показывает сделано / всего. При выполнении всех шагов — «Готово к
  закрытию». Закрыть цель пользователь должен сам. Шаги добавляются по одному.

## Ввод и жесты

- Быстрый ввод: одно многострочное поле, туда же ссылки и любые пояснения.
  Enter — новая строка внутри задачи. Не разделять автоматически строки на задачи.
- Дополнительные свойства не должны препятствовать быстрому сохранению.
- Тап по задаче — открыть. Основные действия через свайпы без меню троеточия:
  перенос даты / в очередь без даты, важность, удаление. Распределение жестов
  ещё выбирается. Отмена последнего действия должна быть доступна.
- Переключение дней: вправо — предыдущий, влево — следующий. Неделя и месяц
  также листаются жестами. Жест, начатый на задаче, не должен переключать день;
  листание дня разрешено на свободном месте или шапке.
- Желательна отмена встряхиванием iPhone с подтверждением. Поддержку и
  надёжность проверить; предусмотреть видимую альтернативу.
- Календарь месяца показывает количество дел, без названий на сетке.

## Проекты

- В проекте первыми — цели и их прогресс, затем самостоятельные задачи.
- «Информация» — отдельная кнопка и отдельная страница проекта с текстом,
  ссылками и пометками. Не смешивать с основным списком.
- Флажки / обозначения связывают задачи с проектами. Один объект задачи
  доступен из ежедневника, проекта и цели, без создания копий.

## Покупки и желания

- Оба раздела обязательны. В «Покупках» пока менять внешний вид; механика
  старого приложения не опробована достаточно для её пересмотра.
- Раздел «Мне надо» — желания для себя, крупные покупки, одежда, подарки
  близким. Название рабочее, ещё выбирается.
- На карточке одновременно видны: свой заголовок (если задан), отдельное
  название товара, изображение, цена. Свой заголовок не заменяет название.
- Одна ссылка на карточку. Название, изображение и цена подгружаются по ней.
  Особое внимание Ozon и Wildberries, где старое приложение ошибалось.
  Возможности извлечения надо проверить на реальных ссылках, не обещать
  гарантированного результата до проверки. Нужна возможность исправить данные.
- Можно добавить желание без ссылки, текстом; дополнить его позже.
- Допрасходы задаются отдельно от базовой цены и видны в карточке другим
  оформлением, например 12 300 ₽ + ≈20 000 ₽. Не прятать их в название.
- Выполненные желания уходят в отдельный список, открываемый кнопкой внизу.

## Итоги

- Отдельный раздел с днями, неделями и месяцами.
- В последний день месяца — промежуточная сводка, первого числа — итоги
  предыдущего месяца. Конкретное представление ещё выбирается.
- Количество выполненных задач + значимые результаты и закрытые цели.
- Сравнение с предыдущим аналогичным периодом.
- Распределение выполненных задач по проектам: столбцы / диаграмма,
  количество и проценты, включая «Без проекта». Это доля задач, не времени.
- Цели считаются отдельно от шагов; нет двойного учёта.
- Без показателей «вовремя / просрочено», гор, свечения и цветов референса.
  Нет таймера и ручного учёта времени.

## Устройства, данные, доступ

- iOS, Android, macOS и Windows, единая PWA; iPhone и Mac — приоритет.
  Требование полноценной работы без сети: ввод, правки, выполнение.
- Автоматическая синхронизация после восстановления связи. Все части модели,
  включая проекты, цели и их связи, должны поддерживаться с самого начала.
- Перенести актуальные задачи из Notes. Импорт — отдельный согласованный этап
  с резервной копией и проверкой на вымышленных данных до работы с реальными.
- Другие пользователи — только по приглашению владельца. Отдельные аккаунты
  со своими задачами, проектами и покупками; личные данные изолированы.
- В первой версии одна тема. Конкретный внешний вид ещё выбирается.
- Архитектура, хостинг, вход, сервер и формат миграции ещё не выбраны.

## Не включать в первую версию

Напоминания, повторяющиеся задачи, ИИ-помощник, вторую тему, второй срок задачи,
файловые папки проекта, несколько товарных ссылок. См. BACKLOG.md.

## Выбор направления после первых макетов

Владелец выбрал структуру «День и запас» (третий вариант), но отверг бежевую
палитру, похожую на старое Notes, и высокие строки. Нужна компактность: время,
название и проект не должны автоматически занимать три отдельных строки.
Короткая задача — одна строка; длинное название переносится по необходимости.
Палитра, типографика и конкретные обозначения пока находятся на согласовании.

## Основной экран для согласования

Устройство владельца — iPhone 17 Pro Max. Следующие макеты и проверку
компоновки ориентировать прежде всего на него: фактическую полезную ширину,
системный масштаб текста, безопасные зоны и режим открытия приложения.
Не приравнивать физическое разрешение дисплея к CSS-размеру интерфейса.
Числовые параметры проверить до следующего макета; они пока не зафиксированы.
Адаптацию под остальные размеры и MacBook выполнить после итогового
согласования основной мобильной версии. Требование поддержки MacBook остаётся.

## Уточнения навигации, жестов и оформления

- Нижняя панель: «Сегодня», «Проекты», центральная кнопка +, «Ещё», «Итоги».
  «Итоги» — крайний правый пункт. «Сегодня» — название по запросу владельца;
  альтернативы для обсуждения: «Мой день», «Дела», «Ежедневник».
- Календарь открывается только из шапки раздела «Сегодня», без отдельной вкладки.
- Текущая плотность строк согласована: короткая задача около 44–45 px,
  время, название и проект в одной строке. Не увеличивать высоту без причины.
- Предыдущая сине-серая палитра отвергнута как слишком офисная. Требуется
  более выразительное оформление. «Графит + лайм» — новое предложение,
  пока не согласованное владельцем.
- Свайп по ленте недели перемещает ленту на целую неделю, не на соседний день.
  В предложенном прототипе открытый день сохраняется до нажатия на новую дату.
- Свайпы по свободной области дня переключают день; по задаче — действия
  только с задачей. Месяцы календаря также листаются отдельно.
- Переходы дня, недели и месяца направленно анимировать; не заменять резким
  скачком. Уважать системное уменьшение движения.
- Новый прототип проверен при фактической ширине поверхности 440 px. Высота
  полезной области на самом телефоне зависит от режима запуска и системных зон.
  Полная проверка сенсорных жестов на iPhone ещё предстоит.

## Следующие уточнения оформления

- Лайм / фирменную пару MOST не использовать как общую палитру Daily.
  Цвета конкретного проекта допустимы только в его собственном контексте.
  Графит в личном интерфейсе владельцу подходит. Новое предложение —
  нейтральный графит, без лаймовых кнопок и выделений.
- «На день» на текущем дне переименовать в «На сегодня».
- Кнопка очереди сверху — «В очереди», секция снизу — «Очередь задач».
- Важность должна быть заметным обозначением слева от названия, сразу после
  квадратика выполнения. Тонкая полоса справа отвергнута. Не применять типовые
  эмодзи или восклицательные знаки. Предложен заполненный геометрический значок;
  конкретный символ пока согласовывается.
- Прямой переход к цели справа в строке сохранить. Стрелку заменить более
  крупным символом. Предложен значок слоёв / группы задач с увеличенной областью
  нажатия; окончательный вид пока не утверждён.

## Цвет и значки — последнее уточнение

Полностью графитовая палитра также отвергнута как офисная. Нужен альтернативный
цветовой акцент, не лайм MOST. Предложены «Петроль» и «Клюква» отдельными
макетами для телефона; выбор пока не сделан. Графит остаётся нейтральной основой.
Значок важности уменьшить относительно крупной плашки с ромбом, сохранив
положение сразу после галочки. Переход к цели вернуть к стрелке, оставить
увеличенный размер и область нажатия, убрать видимую фоновую подложку.

## Выбрана петрольная палитра с ограниченными акцентами

Оставляем петроль, но только в местах, выделявшихся лаймом в прежнем варианте:
выбранная дата, центральный +, основные кнопки действия. Общий текст, время,
метки проектов, блок незавершённого и остальные поверхности нейтральные.
Маленький знак важности слева и крупная стрелка к цели без подложки сохраняются.
Не распространять петроль на все элементы или фирменное оформление проектов.

## Первый тестовый выпуск 0.1.0 — 2 ноября 2026

Разрешена отдельная публикация. Реальные задачи Notes пока не переносить и
не синхронизировать: владелец сначала тестирует Daily вручную с пустой базой.
У Daily собственный приватный Site, отдельная D1 и IndexedDB. Вход через ChatGPT,
доступ только владельцу. Приглашения другим пользователям ещё не открыты.

Реализованы задачи, цели, проекты и информация, календарь, покупки, желания,
итоги, отмена, офлайн-оболочка и собственная синхронизация. Карточки товаров
получают доступные JSON-LD / OG данные, с ручным исправлением. Корректность
Ozon / Wildberries и жеста встряхивания требует проверки на реальном iPhone.
Все проверки выполнялись с вымышленными записями в отдельной локальной базе.

## Единый дизайн — 2 ноября 2026, версия 0.3

Согласованное окно добавления сохранено. Остальные экраны приведены к его
петрольным акцентам, нейтральным поверхностям, скруглениям и крупным зонам нажатия.
Календарь подписан; повторное нажатие «Сегодня» не запускает анимацию недели.
В проектах — явное редактирование, заметные кнопки добавления блока и задачи,
возврат кнопкой и свайпом от левого края. Проект — любая группа, включая личное.
Символ проекта может быть текстом, эмодзи или автоматически подготовленной
миниатюрой загруженного изображения. Миниатюра сохраняется в существующем поле
symbol до 3000 символов: формат и идентификаторы записей не меняются.
При создании блока можно по одной добавить составные задачи. Блок и задачи
сохраняются одной операцией; задачи начинают без даты в очереди.

## Правки 032–034 · 2 ноября 2026

Левый свайп задачи открывает выбор из трёх обозначений: ромб, звезда, флажок,
либо снятие отметки. Все три пока равнозначны прежнему «важно», петрольные,
расположены слева от названия после checkbox. Старые важные задачи — ромбы.
Выбор доступен также в редакторе и по нажатию существующего обозначения;
правый свайп по-прежнему переносит. Ручной порядок остаётся приоритетнее
автоматической сортировки.

Повторное нажатие нижнего «Сегодня» на текущем дне плавно прокручивает к
началу без render. При reduced-motion прокрутка без анимации. Из другого дня
или раздела кнопка возвращает к текущему дню.

Поиск доступен из шапки дня и календаря, общий для всех дат, очереди и
выполненных задач. Ищет по тексту задачи, проекту и блоку, без учёта регистра
и различия е/ё; все слова запроса должны присутствовать. Удалённое исключено.
Выдача локальная, без сетевых запросов; дата результата открывает нужный день.


## Смысл личного списка желаемого · уточнение владельца 2 ноября 2026

Раздел с рабочим названием «Мне надо» задуман как личный мотивационный список
необязательных, но желанных вещей: того, что пользователь хочет получить,
купить для себя или подарить близкому. Подарок маме (например, новый iPhone)
соответствует смыслу раздела: пользователь хочет его подарить. При необходимости
списком можно поделиться скриншотом.

Это не подборка вещей, к которым только присматриваются. Название «На примете»
отклонено; «Желания» владельцу тоже не подходит как окончательное название.

## Чтение задачи и редактирование · решение 2 ноября 2026

В списке показывается превью текста задачи максимум в две строки. Полный текст
любой длины, включая абзацы, сохраняется в прежнем поле. Тап открывает полный
просмотр без ввода; редактирование и перенос вызываются явными действиями.
Checkbox выполняет задачу непосредственно из списка. Переходы к проекту/блоку,
обозначения, свайпы, очередь и правила выполнения сохраняются.


## Решения по полному аудиту · 6 ноября 2026

Владелец согласовал весь показанный UI-пакет и приглушённый петроль#3A7771,
начиная с надёжности/управления. Подробный принятый канон — DESIGN.md.

- Личный список называется «Хочу», завершённые записи — «Готово». Включает
  желанное для себя, подарки близким и личные замыслы. Цена/фото необязательны.
- Полный просмотр отделён от изменения у задач, «Хочу» и информации проекта.
  Выполнение задачи доступно непосредственно из просмотра.
- Задачи и блоки — разные единицы. Календарные количества считают активные
  действия: собственная дата задачи, иначе дата открытого блока. Сам блок
  не прибавляется; ручной порядок и фактические даты выполнения сохранены.
- Название проекта до80 символов; компактный чип ограничивает только видимый
  текст. Типы/поля данных не меняются, дополнительного alias нет.
- Поиск охватывает все текущие сущности и пометки с явным выбором области.
- Личная картинка «Хочу» создаётся локально по запросу; цену/пометки выбирает
  владелец. Отправку адресату выбирает сам в системном меню. Есть сохранение PNG.
- Дополнительные акценты — проверенные локальные настройки, не случайный HEX.
- Ошибка записи не считается успехом: ввод остаётся, изменения обратимы,
  повтор сохранения доступен. Черновики восстанавливаются отдельно от записей.

## План дня по проектам · 6 ноября 2026

По решению владельца день начинается общим хронологическим списком задач со
временем. Остальные дела сгруппированы по проектам, затем «Без проекта»;

## Порядок проектов · 6 ноября 2026
Проекты переставляются в режиме «Изменить порядок» кнопками вверх/вниз.
Этот же порядок определяет группы проектов в дне. «По времени» остаётся первой
секцией в хронологическом порядке, «Без проекта» — после проектных групп.
Ранги проектов синхронизируются; новые проекты без ранга идут после заданного порядка.
