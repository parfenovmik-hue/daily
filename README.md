# Daily

Самостоятельный ежедневник. Тестовая версия 0.1.0, без подключения к Notes,
его Google Sheets, Apps Script, ключам или данным. По умолчанию база пустая.

## Запуск

Требуется Node.js 22.13+. Из этой папки:

```
npm ci
npm run dev -- --port 8797 --hostname 127.0.0.1
```

Локально ссылка «Войти через ChatGPT» использует тестовую учётную запись Sites;
в опубликованном приложении вход настоящий. Локальная и опубликованная базы
раздельные. Для локальной D1 сначала соберите приложение и примените миграцию:

```
npm run build
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_flippant_whistler.sql
```

Миграцию применять к каждой новой локальной базе один раз. Процесс публикации
Sites применяет миграции к своей новой базе автоматически. Никакие миграции
старого Notes не выполняются.

## Структура

- `public/daily.js`, `daily.css`, `icons.js`: клиент и согласованный интерфейс.
- `public/model.js`: даты, прогресс, итоги, проверка и объединение записей.
- `public/store.js`: отдельный IndexedDB, атомарное сохранение очереди изменений.
- `public/sw.js`, `offline.html`: офлайн-оболочка и установка PWA.
- `app/api/sync`: синхронизация в D1 по идентификатору вошедшего пользователя.
- `app/api/product`: получение доступных метаданных товара по HTTPS-ссылке.
- `db`, `drizzle`: схема и миграции отдельной серверной базы.
- `.openai/hosting.json`: привязка отдельного Daily к Sites, без ключей.

Полный рабочий каталог можно перенести вместе со всем `daily`; исходники Notes
не нужны для запуска или сборки. Договорённости по продукту находятся рядом,
в `../PRODUCT.md`, будущие функции — в `../BACKLOG.md`.

## Данные и синхронизация

Каждое поле хранится с логическими часами и идентификатором устройства.
Объединение коммутативно: разные поля не перетирают друг друга, повторная
отправка безопасна. При одновременной правке одного поля выигрывает больший
штамп; ничья разрешается идентификатором устройства. Удаление — тоже поле,
поэтому отложенная правка названия сама по себе не восстанавливает удалённое.
Сервер применяет объединение с проверкой ревизии записи и повтором при гонке.

Стабильный ID аккаунта берётся из проверенных заголовков Sites, а не из тела
запроса. Все обращения к D1 ограничены владельцем. IndexedDB также разделён
по аккаунтам. В первой публикации доступ только владельцу; другие пользователи
не приглашены. Отдельного интерфейса выдачи приглашений в этом выпуске нет.

Покупки и желания не включаются в счётчики выполненных задач. Цель закрывается
вручную. Для зачёркнутой задачи день выполнения и исходная назначенная дата
разделены; досрочная отметка не удваивает статистику.

В настройках есть экспорт JSON и отмена последнего действия. Встряхивание
включается вручную с разрешением iPhone; при отсутствии датчиков остаётся
кнопка отмены. Работа жеста встряхивания требует проверки на реальном устройстве.

## Проверки

```
npm test
npm run typecheck
node tests/api-check.mjs
npm run build
```

`api-check` запускается только против отдельного локального preview и создаёт
вымышленную запись, которую затем помечает удалённой. Не направлять этот тест
на production.

Для проверки настоящей офлайн-оболочки на localhost откройте
`/?offline-test=1`. Обычный dev-просмотр SW не регистрирует. У опубликованной
версии SW включается автоматически по HTTPS. Кэш относится только к Daily.

## Ограничения первого тестового выпуска

Карточки товаров разбираются из доступных метаданных страницы (JSON-LD / OG).
Некоторые магазины, включая Ozon и Wildberries, могут не отдавать эти данные
серверу. Блокировки не обходятся: ссылка сохраняется, а поля можно заполнить
вручную. Качество этих двух источников нужно отдельно проверить на реальных
ссылках владельца. Внешние AI-ключи и старый Anthropic API не используются.

Напоминания, повторения, AI-помощник, импорт Notes и выдача приглашений новым
пользователям в этот тестовый выпуск не входят. Приложение создаёт только
собственные данные Daily.
