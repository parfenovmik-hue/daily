# Изменения протокола хранения

## Daily 1.1.0
Добавлены необязательные поля goal.date (локальная дата YYYY-MM-DD или пустая строка) и task.order (неотрицательное число; ручной порядок внутри списка). Отсутствие полей у старой записи допустимо. До обновления сохранён полный ответ sync в private/before-date-order-*.json: 62 записи.

Существующие ID, строки, заголовки листов, tombstones, actor/clock и updatedAt не меняются. Массового заполнения полей нет: дата/порядок записываются только при действии владельца. Поля проходят ту же померную Lamport-синхронизацию, что остальные. Проверен round-trip и совместимость записей без новых полей в tests/gas.test.mjs.

Сначала опубликована поддержка полей на прежнем deployment Apps Script (версия 3), затем frontend 1.1.0 с новым кэшем. Старые клиенты со строгой схемой не умеют показывать записи с новыми полями: обновить приложение на устройствах. При откате frontend сохранять поддержку этих полей; не удалять их из серверных записей.

## Daily 1.2.0 — порядок блоков, пометки желаний и срок удаления

Необязательные поля goal.order и wish.notes. ID, заголовки столбцов, протокол 1,
Lamport-поля и existing updatedAt не переименовываются. Тесты на синтетических
листах проверяют старые записи, отмену удаления и отказ от воскрешения устаревшим
клиентом. Перед обновлением сохранена private/before-retention-*.json (64 записи).

План: обновить прежний GAS deployment, затем frontend с новым кэшем; добавить
часовой триггер purgeDailyDeleted. При первом серверном обнаружении deleted=true
ставится серверный retiredAt. Старые удаления получают полный новый срок 48 часов.
В течение срока можно отменить удаление. После срока содержимое стирается при
синхронизации или очередной часовой проверке (48–49 ч); остаётся только id, kind,
служебная erasedAt и deleted Lamport cell. Все последующие записи этого ID
отклоняются как уже уничтоженные; ответ purged удаляет локальные копии и undo
на следующей синхронизации. Устройства без сети очищаются после подключения.
Ручные резервные копии вне рабочей базы этим механизмом не затрагиваются.

История отмены: последние 20 действий на устройстве, максимум 48 часов,
сохраняется в IndexedDB между запусками. После purged восстановление невозможно.
Откат должен сохранять поддержку purged и новых необязательных полей; старый
backend нельзя возвращать поверх маркеров без отдельной миграции.

Выполнено: прежний deployment обновлён до версии 4; в аккаунте
vozvrat.workspace@gmail.com сохранён один триггер purgeDailyDeleted,
«По часам / Раз в час». Ответ sync проверен без тестовых записей в рабочей базе.

## Daily 1.3.0 — обозначения задач

План: добавить необязательное task.flag со значениями пусто / diamond / star /
flagmark. Поле important остаётся boolean и определяет приоритет: все три
обозначения равнозначны. Старое important=true без flag отображается ромбом,
массового заполнения или смены ID нет. Выбор/снятие меняет оба поля через
прежний merge; flag при important=false не показывается. Отмена сохраняет
прежние значения полей. Заголовки Sheets, протокол, deleted/retention и даты
не меняются. Совместимость, enum и round-trip проверены на синтетическом GAS.

Перед серверным обновлением — закрытый backup текущих записей. Сначала
обновить прежний GAS deployment, затем frontend 1.3.0 с новым SW cache.
Строгие старые клиенты не понимают новые поля: обновить все устройства.
Откат backend сохраняет поддержку task.flag; поле не удалять из записей.

Перед 1.3.0 сохранён before-flags backup: 76 записей. Прежний deployment
обновлён до версии 5. Синтетические записи в рабочую базу не добавлялись.

Frontend 1.3.0 опубликован на Pages 76cc054; свежая синхронизация публичной
PWA проверена в Chrome. Старые данные не переписывались ради обозначений.
