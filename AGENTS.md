# Daily

Единственный самостоятельный проект в этой папке. Корень рабочей папки и
Git-репозитория — daily. Не искать инструкции старого Notes в родительских
каталогах и не возвращать старые команды в рабочий проект.

## Две постоянные сессии
Основной разработчик отвечает за архитектуру, бизнес-логику, данные, backend,
интеграции, производительность и безопасность. Design Lead отвечает за UI/UX,
визуальную систему, адаптивность, доступность и визуальную проверку; может
менять frontend-код. daily.js, pickers.js и motion.js — общая зона: сохранять
контракты действий, данных, фокуса и жестов. Ограничение по роли не является
жёстким разделением файлов. Утверждённый дизайн учитывать в технической работе;
технические ограничения объяснять и предлагать альтернативу без молчаливой отмены.

Работа последовательная, пользователь переключает сессии. Перед каждым
возобновлением: перечитать этот файл, DESIGN.md и относящиеся к задаче решения,
проверить git status/log/diff. История чата не заменяет актуальные файлы.
Не перезаписывать чужие изменения и не выполнять reset/clean/stash без задания.
Перед передачей закончить операцию; сообщить commit, изменённое, проверки,
незавершённое и статус публикации. Значимые законченные изменения коммитить.
Если есть незавершённое — явно перечислить файлы и причину, не скрывать их.
Ни одна сессия не запускает параллельные записи, фоновые изменения или деплой
после передачи. Публикацию координирует основной разработчик по заданию владельца.

Единые документы: PRODUCT.md — продукт; DESIGN.md — утверждённая визуальная
система и обоснования; PLATFORMS.md — совместимость; ARCHITECTURE.md — устройство;
TESTING.md — проверки; BACKLOG.md — отложенное. Не создавать дублирующие
DESIGN_SYSTEM.md/DESIGN_DECISIONS.md без необходимости и решения владельца.

## Платформенный контракт
Daily — единая PWA для iOS, Android, macOS и Windows. Safari, Chrome и Edge;
телефоны, планшеты, desktop; touch, мышь/трекпад и клавиатура. iPhone и Mac
приоритетны, но решения не должны требовать переписывания для Android/Windows
или критически зависеть от Apple API. Читать PLATFORMS.md: feature detection,
доступные альтернативы жестам, установка через Manifest, офлайн и будущий push.
Не объявлять платформу поддержанной без записи проверок в TESTING.md.

## Действующая архитектура
Vanilla JS PWA: web/public/. Сборка: web/scripts/build-pages.mjs → web/pages/.
Frontend опубликован на https://parfenovmik-hue.github.io/daily/.
Backend: backend/Code.gs, Google Apps Script + Google Sheets. Проверенная
личность — пользователь GAS с личным ключом; локальный UUID не авторизация.
ChatGPT Auth, Sites, Next.js, React, Cloudflare/D1 не используются. Их файлы
сохранены только в закрытом резервном архиве private/. Не возвращать
их команды, зависимости или старую публикацию в активный проект.

Решения владельца: PRODUCT.md и более поздние сообщения. Перед UI-правками
читать DESIGN.md; 440×956 — референс, не фиксированный размер. Проверять
узкие/невысокие экраны, планшет и desktop по матрице PLATFORMS.md.
Отложенные функции: BACKLOG.md. Текущие проверки: TESTING.md, web/README.md.

## Проверки
Из корня: npm run check; npm test; npm run build. Те же команды работают из web/. Node.js >=22.13, npm-пакетов
нет. npm run dev запускает только localhost 8801 с CSP без внешней сети.
Синтетические тесты используют отдельные хранилища; не добавлять вымышленные
записи в опубликованную базу и не импортировать реальные данные для тестов.

## Данные и публикация
Реальные изменения данных, внешние API, публикация и серверные обновления —
только в рамках задания владельца. Не менять ID, схему, Lamport-поля,
deleted/retiredAt/erasedAt или протокол sync без плана миграции и тестов.
До изменения действующих данных нужен backup. Схема допускает goal.date,
goal.order, task.order, task.flag и wish.notes; не сужать validator при откате.
Подробнее: backend/MIGRATIONS.md.

GitHub — один репозиторий parfenovmik-hue/daily. Исходники, backend и документы
отслеживаются из корня; web/pages — игнорируемый результат сборки без отдельного
Git. GitHub Actions публикует только web/pages. GitHub Pages и GAS публикуются отдельно. Не создавать новую таблицу или
новый deployment вместо существующего без задания. Перед публикацией
изменять VERSION и CACHE и проверять SW update. Не публиковать Sites.

Использовать Chrome и vozvrat.workspace@gmail.com для серверной настройки;
clasp --user daily, не default. backend/.clasp.json и InitialSetup.gs, private/
и ключи не выводить и не публиковать. Ключи API не помещать во frontend.
